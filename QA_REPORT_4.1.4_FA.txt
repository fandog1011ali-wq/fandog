گزارش اصلاح و آزمون TITAN 4.1.4
================================

اصلاح مهم نسبت به 4.1.3:
- در GitHub Pages، اگر لینک پلی‌لیست HTTP باشد و Worker تنظیم نشده باشد، پلیر دیگر فوراً متوقف نمی‌شود؛ ابتدا همان میزبان/مسیر را با HTTPS امتحان می‌کند.
- پورت HTTP استاندارد 80 به HTTPS استاندارد 443 نگاشت می‌شود؛ پورت سفارشی حفظ می‌شود.
- لینک لوگوهای HTTP نیز در نسخه استاتیک به‌صورت best-effort با HTTPS امتحان می‌شوند.
- نسخه Legacy نیز همین ارتقا را برای لینک‌های HTTP انجام می‌دهد.
- در صورت شکست پخش، دکمه «باز کردن لینک اصلی در تب جدید» برای امتحان منبع خام نمایش داده می‌شود.
- شناسه کش Service Worker به v414 افزایش یافت.

آزمون‌های قابل اجرا در محیط ساخت:
- بررسی نحو JavaScript برای اسکریپت inline در modern.html، legacy.js، compat-check.js و sw.js انجام شد.
- تست تابع تبدیل URL: HTTP پورت 80 به HTTPS بدون پورت تبدیل می‌شود؛ پورت سفارشی حفظ می‌شود؛ URLهای HTTPS بدون تغییر می‌مانند.
- تست ساختار M3U و وجود هر چهار فایل playlist انجام شد.
- سلامت ZIP کامل و بسته Patch بررسی شد.

محدودیت مهم و اجتناب‌ناپذیر:
- این نسخه فقط در صورت داشتن TLS واقعی روی همان میزبان، می‌تواند HTTP را به HTTPS ارتقا دهد. تبدیل متن URL، سرور HTTP را به سرور HTTPS تبدیل نمی‌کند.
- اگر سرور نسخه HTTPS نداشته باشد، یا CORS را برای HLS.js/DASH.js نبندد، پخش در GitHub Pages بدون پراکسی/Worker ممکن نیست.
- Worker داخل GitHub Pages اجرا نمی‌شود. worker-config.js عمداً خالی است تا URL ساختگی وارد نشود.
- فایل worker.zip ارسالی کاربر یک Worker اختصاصی Telewebion manifest rewriter است، نه سرویس Worker مستقر و نه URL قابل استفاده. کد آن در بسته کامل حفظ شده و با پراکسی عمومی TITAN ادغام شده است.
- 542 لینک HTTP و 136 لینک HTTPS در چهار M3U وجود دارد؛ هیچ راه مرورگری برای تضمین پخش تمام لینک‌های HTTP بدون یک واسط HTTPS وجود ندارد.
- پخش زنده واقعی در این محیط به دلیل نبود دسترسی DNS/شبکه به ارائه‌دهندگان قابل تأیید نبود.

برای اعمال روی GitHub:
- فایل‌های modern.html، legacy.js و sw.js را در ریشه مخزن با نسخه‌های این بسته جایگزین کنید.
- پس از موفقیت Pages deployment، صفحه را با Ctrl+Shift+R تازه‌سازی کنید.
