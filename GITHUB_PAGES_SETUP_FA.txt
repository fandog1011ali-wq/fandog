راهنمای اصلاح TITAN برای GitHub Pages — نسخه 4.0.1
====================================================

علت خالی بودن فهرست کانال‌ها
----------------------------
نسخه قبلی رابط مدرن و Legacy برای گرفتن فهرست‌ها به api.php?list=... درخواست می‌فرستاد.
GitHub Pages فقط فایل استاتیک میزبانی می‌کند و PHP را اجرا نمی‌کند؛ در نتیجه فهرست‌ها بارگذاری نمی‌شدند.

اصلاح انجام‌شده
---------------
1) modern.html در دامنه github.io چهار فایل زیر را مستقیم می‌خواند:
   playlists/live.m3u
   playlists/list1.m3u
   playlists/list2.m3u
   playlists/list3.m3u
2) legacy.js نیز در مرورگرهای قدیمی همین فایل‌ها را با XMLHttpRequest می‌خواند.
3) در حالت GitHub Pages، فراخوانی APIهای PHP برای فهرست‌ها، لوگو، سلامت سرور، FFprobe، پراکسی و FFmpeg انجام نمی‌شود.
4) نسخه PHP پروژه حفظ شده است؛ روی هاست PHP، مسیرهای قبلی همچنان استفاده می‌شوند.
5) Service Worker به نسخه 4.0.1 ارتقا یافته تا کش نسخه قبلی با نسخه جدید مخلوط نشود.
6) فایل .nojekyll اضافه شده است.

محدودیت‌های واقعی نسخه GitHub Pages
-----------------------------------
- فهرست کانال‌ها از فایل‌های M3U خود مخزن خوانده می‌شود و برای نمایش کانال‌ها PHP لازم نیست.
- پخش مستقیم فقط وقتی ممکن است که مرورگر کدک/قالب را پشتیبانی کند.
- منبع HTTP از صفحه HTTPS ممکن است به‌عنوان Mixed Content مسدود شود؛ لینک HTTPS لازم است.
- HLS.js و DASH.js به CORS صحیح از سرور استریم نیاز دارند.
- GitHub Pages نمی‌تواند RTSP/RTMP/UDP/SRT را به پخش مرورگری تبدیل کند.
- تبدیل کدک، FFmpeg، FFprobe و پراکسی استریم فقط روی سرور PHP/VPS قابل اجرا هستند.
- URLهای رمزدار/توکن‌دار در M3U داخل مخزن عمومی برای همه قابل مشاهده‌اند؛ فقط منابعی را منتشر کنید که اجازه انتشار و استفاده از آن‌ها را دارید.

تست محلی
---------
در یک وب‌سرور استاتیک، فایل modern.html را با پارامتر ?titanStatic=1 باز کنید تا مسیر GitHub Pages شبیه‌سازی شود.
فایل‌های M3U باید در پوشه playlists و با نام‌های دقیق بالا باشند.
